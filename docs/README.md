# OctoAcme Project Management Docs

This directory contains the core project management guidance used by OctoAcme to plan, execute, and improve cross-functional work.

## Overview

OctoAcme runs work through a lightweight, iterative lifecycle that starts with validating a business problem and aligning stakeholders, then moves into planning, execution, release, and continuous improvement.

- Initiation: confirm the need, define success metrics, identify stakeholders, and decide whether to move forward.
- Planning: create a backlog, estimate work, define milestones, and document dependencies and risks.
- Execution: manage day-to-day delivery through a project board, standups, reviews, and clear ownership.
- Release & deployment: prepare production changes, validate them with smoke tests, communicate status, and handle rollback if needed.
- Retrospective: capture lessons learned and convert them into tracked improvement actions.

OctoAcme emphasizes customer value, iterative delivery, clear ownership, and measurable outcomes. Project Managers coordinate schedules, risk, and communication; Product Managers define outcomes and priorities; developers build and validate the work; QA validates acceptance criteria; and stakeholders provide feedback and approvals.

## How to Use This Guide

Use this README as the entry point for OctoAcme project management practices. Start with the overview and initiation guide if a project is just beginning, then move through planning, execution, and release guidance as work progresses.

For a new initiative, begin with the project initiation checklist and create the core project artifacts. For ongoing work, use the execution, risk, and release documents to keep delivery on track and maintain visibility across stakeholders.
